## 1. 数据库架构概述

### 1.1 双数据库架构

本系统采用**PostgreSQL + TDEngine**双数据库架构，根据数据特性选择合适的存储方案。

#### PostgreSQL（关系型数据库）
**用途**：存储管理类数据（低频更新、强一致性要求）
- `rtu_gateway`：RTU 网关管理表
- `rtu_config`：RTU 配置表
- `rtu_alarm`：RTU 报警表

**特点**：
- ✅ 支持复杂查询和事务处理
- ✅ 适合低频更新的管理数据
- ✅ 提供强一致性保证
- ✅ 支持外键约束和数据完整性

#### TDEngine（时序数据库）
**用途**：存储时序采集数据（高频写入、时间序列查询）
- `rtu_data`：RTU 温湿度采集数据（超表）

**特点**：
- ✅ 高性能写入（每秒百万级数据点）
- ✅ 高压缩比（1/10 存储空间）
- ✅ 自动分区和时间索引
- ✅ 针对时序数据优化的聚合查询
- ✅ 支持数据保留策略（自动清理过期数据）

### 1.2 数据流向

```
serial-collector (边缘采集)
    ↓ (二进制帧封装 Modbus 数据)
rtu-gateway (协议转换)
    ↓ (MQTT JSON格式)
MQTT Broker (Mosquitto)
    ↓ (MQTT订阅)
web-server (业务服务)
    ├───────────────┬────────────────┐
    ↓               ↓                ↓
PostgreSQL      TDEngine        Redis(可选)
(管理数据)      (时序数据)       (缓存热点数据)
```

**数据分类存储**：
- **管理数据** → PostgreSQL
  - RTU 注册信息（rtu_id、name、secret、status）
  - RTU 配置参数（interval、threshold、calibration）
  - 报警记录（alarm_type、alarm_value、status）

- **采集数据** → TDEngine
  - 温湿度实时数据（temperature、humidity、timestamp）
  - 历史数据查询（按时间范围检索）
  - 统计数据（avg、max、min）

## 2. PostgreSQL 数据库设计

### 2.1 rtu_gateway 表 (RTU 网关管理表)

**用途**：管理所有 RTU 边缘采集设备的注册信息、认证密钥、在线状态

```sql
CREATE TABLE rtu_gateway (
    id BIGSERIAL PRIMARY KEY,                              -- 自增主键 ID
    rtu_id VARCHAR(64) NOT NULL UNIQUE,                    -- RTU 唯一标识（如 RTU-001）
    name VARCHAR(64) NOT NULL,                             -- RTU 名称（如"1 号车间工控机"）
    location VARCHAR(256),                                 -- 安装位置描述
    status VARCHAR(32) DEFAULT 'ENABLED' NOT NULL,         -- 网关状态：ENABLED（允许采集）/DISABLED（禁止采集）
    online VARCHAR(32) DEFAULT 'OFFLINE' NOT NULL,         -- 在线状态：ONLINE/OFFLINE
    secret VARCHAR(128) NOT NULL,                          -- 认证密钥（用于二进制帧认证，SHA-256 哈希）
    heartbeat_time TIMESTAMP,                              -- 最后心跳时间
    create_time TIMESTAMP DEFAULT NOW() NOT NULL,          -- 创建时间
    update_time TIMESTAMP DEFAULT NOW() NOT NULL           -- 更新时间
);

-- 创建索引
CREATE INDEX idx_rtu_gateway_rtu_id ON rtu_gateway(rtu_id);
CREATE INDEX idx_rtu_gateway_status ON rtu_gateway(status);
CREATE INDEX idx_rtu_gateway_online ON rtu_gateway(online);
CREATE INDEX idx_rtu_gateway_create_time ON rtu_gateway(create_time);

-- 添加表注释
COMMENT ON TABLE rtu_gateway IS 'RTU 网关管理表（边缘设备）';
COMMENT ON COLUMN rtu_gateway.rtu_id IS 'RTU 唯一标识（如 RTU-001），全局唯一';
COMMENT ON COLUMN rtu_gateway.name IS '网关名称（如"1 号车间工控机"）';
COMMENT ON COLUMN rtu_gateway.location IS '安装位置描述（如"机房 A 区 -1 号柜"）';
COMMENT ON COLUMN rtu_gateway.status IS '网关状态：ENABLED（允许采集）/DISABLED（禁止采集）';
COMMENT ON COLUMN rtu_gateway.online IS '在线状态：ONLINE（在线）/OFFLINE（离线）';
COMMENT ON COLUMN rtu_gateway.secret IS '认证密钥（用于二进制帧认证，SHA-256 哈希存储）';
COMMENT ON COLUMN rtu_gateway.heartbeat_time IS '最后心跳时间（用于判断 RTU 是否在线）';
COMMENT ON COLUMN rtu_gateway.create_time IS '创建时间';
COMMENT ON COLUMN rtu_gateway.update_time IS '更新时间';
```

**状态说明**：

| 字段 | 取值 | 说明 |
|------|------|------|
| `status` | ENABLED | 允许 RTU 采集和上报数据 |
| `status` | DISABLED | 禁止 RTU 上报数据（认证时拒绝连接） |
| `online` | ONLINE | RTU 当前在线（有心跳） |
| `online` | OFFLINE | RTU 当前离线（无心跳） |

**状态控制流程**：
1. 管理员在 web 界面注册 RTU，默认 `status=ENABLED`, `online=OFFLINE`
2. RTU 连接到 rtu-gateway，发送认证帧（包含 rtu_id + secret）
3. rtu-gateway 调用 web-server API 验证：`POST /api/rtu/gateway/verify`
4. web-server 查询 `rtu_gateway` 表：
   - 如果 `status=DISABLED` → 返回认证失败，拒绝连接
   - 如果 `status=ENABLED` → 返回认证成功，设置 `online=ONLINE`
5. RTU 每 30 秒发送心跳，更新 `heartbeat_time`
6. RTU 断开连接或超时（90 秒无心跳），设置 `online=OFFLINE`

**示例数据**：
```sql
INSERT INTO rtu_gateway (rtu_id, name, location, status, online, secret) VALUES
('RTU-001', '1 号车间工控机', '机房 A 区 -1 号柜', 'ENABLED', 'ONLINE', 'abc123xyz'),
('RTU-002', '2 号车间工控机', '机房 B 区 -2 号柜', 'ENABLED', 'OFFLINE', 'def456uvw'),
('RTU-003', '3 号车间工控机', '机房 C 区 -3 号柜', 'DISABLED', 'OFFLINE', 'ghi789rst');
```

### 2.2 rtu_config 表 (RTU 配置表)

**用途**：存储每个 RTU 的配置参数，包括采集间隔、Modbus 参数、报警阈值、校准值等

```sql
CREATE TABLE rtu_config (
    id BIGSERIAL PRIMARY KEY,                              -- 自增主键 ID
    rtu_id VARCHAR(64) NOT NULL UNIQUE,                    -- RTU 唯一标识（外键关联 rtu_gateway）
    interval INT DEFAULT 1 NOT NULL,                       -- 采集间隔（秒），范围 1-60
    modbus_device_address INT DEFAULT 1 NOT NULL,          -- Modbus 设备地址（1-254）
    baud_rate INT DEFAULT 4800 NOT NULL,                   -- 串口波特率（1200/2400/4800/9600/19200/38400/57600/115200）
    temp_calibration DECIMAL(10,2) DEFAULT 0.0,            -- 温度校准值（℃）
    humidity_calibration DECIMAL(10,2) DEFAULT 0.0,        -- 湿度校准值（%RH）
    temp_threshold_min DECIMAL(10,2),                      -- 温度报警下限（℃）
    temp_threshold_max DECIMAL(10,2),                      -- 温度报警上限（℃）
    humidity_threshold_min DECIMAL(10,2),                  -- 湿度报警下限（%RH）
    humidity_threshold_max DECIMAL(10,2),                  -- 湿度报警上限（%RH）
    alarm_enabled BOOLEAN DEFAULT TRUE,                    -- 是否启用报警
    create_time TIMESTAMP DEFAULT NOW() NOT NULL,          -- 创建时间
    update_time TIMESTAMP DEFAULT NOW() NOT NULL           -- 更新时间
);

-- 创建索引
CREATE INDEX idx_rtu_config_rtu_id ON rtu_config(rtu_id);
CREATE INDEX idx_rtu_config_interval ON rtu_config(interval);

-- 添加外键约束（可选，根据业务需求）
-- ALTER TABLE rtu_config ADD CONSTRAINT fk_rtu_config_gateway 
--     FOREIGN KEY (rtu_id) REFERENCES rtu_gateway(rtu_id) ON DELETE CASCADE;

-- 添加表注释
COMMENT ON TABLE rtu_config IS 'RTU 配置表';
COMMENT ON COLUMN rtu_config.rtu_id IS 'RTU 唯一标识（与 rtu_gateway 关联）';
COMMENT ON COLUMN rtu_config.interval IS '采集间隔（秒），范围 1-60 秒';
COMMENT ON COLUMN rtu_config.modbus_device_address IS 'Modbus 设备地址（1-254），通常为 0x01';
COMMENT ON COLUMN rtu_config.baud_rate IS '串口波特率：1200/2400/4800/9600/19200/38400/57600/115200';
COMMENT ON COLUMN rtu_config.temp_calibration IS '温度校准值（℃），用于修正传感器误差';
COMMENT ON COLUMN rtu_config.humidity_calibration IS '湿度校准值（%RH），用于修正传感器误差';
COMMENT ON COLUMN rtu_config.temp_threshold_min IS '温度报警下限（℃），低于此值触发低温报警';
COMMENT ON COLUMN rtu_config.temp_threshold_max IS '温度报警上限（℃），高于此值触发高温报警';
COMMENT ON COLUMN rtu_config.humidity_threshold_min IS '湿度报警下限（%RH），低于此值触发低湿报警';
COMMENT ON COLUMN rtu_config.humidity_threshold_max IS '湿度报警上限（%RH），高于此值触发高湿报警';
COMMENT ON COLUMN rtu_config.alarm_enabled IS '是否启用报警（true=启用，false=禁用）';
COMMENT ON COLUMN rtu_config.create_time IS '创建时间';
COMMENT ON COLUMN rtu_config.update_time IS '更新时间';
```

**配置下发流程**：
1. 管理员在 web 界面修改 RTU 配置
2. web-server 更新 `rtu_config` 表
3. web-server 通过 MQTT发布配置消息到主题：`iot/rtu/{rtuId}/config`
4. rtu-gateway 订阅该主题，接收 JSON 配置
5. rtu-gateway 将 JSON 配置转换为 Modbus 写入命令（功能码 0x06）
6. rtu-gateway 封装为二进制帧（帧类型 0x04）下发到 serial-collector
7. serial-collector 通过串口写入传感器设备
8. 传感器返回响应，确认配置生效

**配置项说明**：

| 配置项 | 寄存器地址 | 说明 | 示例值 |
|--------|-----------|------|--------|
| `modbus_device_address` | 0x07D0 | 设备地址（1-254） | 1 |
| `baud_rate` | 0x07D1 | 波特率代码 | 2=9600 |
| `temp_calibration` | 0x0050 | 温度校准值（扩大 10 倍） | 5=0.5℃ |
| `humidity_calibration` | 0x0051 | 湿度校准值（扩大 10 倍） | 0=0.0%RH |

**波特率代码映射**：
```java
private int getBaudRateCode(int baudRate) {
    switch (baudRate) {
        case 1200: return 7;
        case 2400: return 0;
        case 4800: return 1;
        case 9600: return 2;
        case 19200: return 3;
        case 38400: return 4;
        case 57600: return 5;
        case 115200: return 6;
        default: throw new IllegalArgumentException("Unsupported baud rate");
    }
}
```

**示例数据**：
```sql
INSERT INTO rtu_config (rtu_id, interval, modbus_device_address, baud_rate, temp_threshold_min, temp_threshold_max, humidity_threshold_min, humidity_threshold_max) VALUES
('RTU-001', 1, 1, 9600, 18.0, 28.0, 40.0, 60.0),
('RTU-002', 5, 1, 4800, 15.0, 35.0, 30.0, 70.0),
('RTU-003', 10, 1, 9600, 20.0, 30.0, 45.0, 65.0);
```

### 2.3 rtu_alarm 表 (RTU 报警表)

**用途**：记录所有 RTU 的报警事件，包括报警类型、报警值、阈值、处理状态等

```sql
CREATE TABLE rtu_alarm (
    id BIGSERIAL PRIMARY KEY,                              -- 自增主键 ID
    rtu_id VARCHAR(64) NOT NULL,                           -- RTU 唯一标识
    alarm_type VARCHAR(32) NOT NULL,                       -- 报警类型
    alarm_level VARCHAR(32) DEFAULT 'WARNING' NOT NULL,    -- 报警级别：INFO/WARNING/ERROR
    current_value DECIMAL(10,2) NOT NULL,                  -- 实际触发报警的值
    threshold_value DECIMAL(10,2) NOT NULL,                -- 阈值
    alarm_message TEXT,                                    -- 报警详细描述
    alarm_time TIMESTAMP DEFAULT NOW() NOT NULL,           -- 报警时间
    status VARCHAR(32) DEFAULT 'UNHANDLED' NOT NULL,       -- 处理状态：UNHANDLED（未处理）/HANDLED（已处理）
    handle_result TEXT,                                    -- 处理结果描述
    handler VARCHAR(64),                                   -- 处理人
    handle_time TIMESTAMP                                  -- 处理时间
);

-- 创建索引
CREATE INDEX idx_rtu_alarm_rtu_id ON rtu_alarm(rtu_id);
CREATE INDEX idx_rtu_alarm_time ON rtu_alarm(alarm_time);
CREATE INDEX idx_rtu_alarm_status ON rtu_alarm(status);
CREATE INDEX idx_rtu_alarm_type ON rtu_alarm(alarm_type);

-- 添加表注释
COMMENT ON TABLE rtu_alarm IS 'RTU 报警记录表';
COMMENT ON COLUMN rtu_alarm.rtu_id IS 'RTU 唯一标识';
COMMENT ON COLUMN rtu_alarm.alarm_type IS '报警类型：TEMP_HIGH（高温）/TEMP_LOW（低温）/HUMIDITY_HIGH（高湿）/HUMIDITY_LOW（低湿）';
COMMENT ON COLUMN rtu_alarm.alarm_level IS '报警级别：INFO（提示）/WARNING（警告）/ERROR（错误）';
COMMENT ON COLUMN rtu_alarm.current_value IS '实际触发报警的值';
COMMENT ON COLUMN rtu_alarm.threshold_value IS '阈值（超过或低于此值触发报警）';
COMMENT ON COLUMN rtu_alarm.alarm_message IS '报警详细描述';
COMMENT ON COLUMN rtu_alarm.alarm_time IS '报警时间';
COMMENT ON COLUMN rtu_alarm.status IS '处理状态：UNHANDLED（未处理）/HANDLED（已处理）';
COMMENT ON COLUMN rtu_alarm.handle_result IS '处理结果描述';
COMMENT ON COLUMN rtu_alarm.handler IS '处理人';
COMMENT ON COLUMN rtu_alarm.handle_time IS '处理时间';
```

**报警类型枚举**：

| 报警类型代码 | 说明 | 触发条件 | 示例 |
|------------|------|----------|------|
| `TEMP_HIGH` | 温度过高 | 温度 > temp_threshold_max | 温度 32℃ > 阈值 28℃ |
| `TEMP_LOW` | 温度过低 | 温度 < temp_threshold_min | 温度 15℃ < 阈值 18℃ |
| `HUMIDITY_HIGH` | 湿度过高 | 湿度 > humidity_threshold_max | 湿度 65% > 阈值 60% |
| `HUMIDITY_LOW` | 湿度过低 | 湿度 < humidity_threshold_min | 湿度 35% < 阈值 40% |

**报警级别定义**：

| 级别 | 说明 | 颜色标识 | 通知方式 |
|------|------|----------|----------|
| `INFO` | 提示信息 | 蓝色 | 仅记录日志 |
| `WARNING` | 警告 | 黄色 | 前端弹窗提醒 |
| `ERROR` | 错误 | 红色 | 短信/邮件通知 |

**报警处理流程**：
1. web-server 接收到 MQTT 数据消息
2. 从 `rtu_config` 表读取报警阈值
3. 判断数据是否超出阈值范围
4. 如果超出阈值，在 `rtu_alarm` 表插入报警记录（`status=UNHANDLED`）
5. 管理员在前端查看报警列表
6. 管理员处理报警并填写处理结果
7. 更新报警记录（`status=HANDLED`, `handle_result`, `handler`, `handle_time`）

**示例数据**：
```sql
INSERT INTO rtu_alarm (rtu_id, alarm_type, alarm_level, current_value, threshold_value, alarm_message, status) VALUES
('RTU-001', 'TEMP_HIGH', 'WARNING', 32.0, 28.0, '温度超过上限（32.0℃ > 28.0℃）', 'UNHANDLED'),
('RTU-001', 'HUMIDITY_LOW', 'INFO', 35.0, 40.0, '湿度低于下限（35.0% < 40.0%）', 'HANDLED'),
('RTU-002', 'TEMP_LOW', 'ERROR', 12.0, 15.0, '温度低于下限（12.0℃ < 15.0℃）', 'UNHANDLED');
```

## 3. TDEngine 时序数据库设计

### 
3.1 rtu_data 超表 (RTU 数据采集表)
**用途**：存储所有 RTU 的温湿度采集数据（每秒 1 条，高频写入）

```sql
-- 创建数据库
CREATE DATABASE IF NOT EXISTS iot_rtu
VARIABLES KEEP 3650      -- 数据保留 3650 天（10 年）
          BLOCKS 4       -- 内存块数量
          CACHE 16MB     -- 缓存大小
          WAL_LEVEL 2    -- WAL 日志级别
          PRECISION 'ms'; -- 时间戳精度（毫秒）

-- 使用数据库
USE iot_rtu;

-- 创建超级表（STable）
CREATE STABLE IF NOT EXISTS rtu_data (
    ts TIMESTAMP,                    -- 时间戳（主键，自动索引）
    temperature FLOAT,               -- 温度值（℃），范围 -40~85
    humidity FLOAT                   -- 湿度值（%RH），范围 0~100
) TAGS (
    rtu_id NCHAR(64)                 -- RTU 标识（标签，用于分组查询）
);

-- 添加表注释
COMMENT ON STABLE rtu_data IS 'RTU 温湿度数据采集超表';
COMMENT ON COLUMN rtu_data.ts IS '时间戳（毫秒精度）';
COMMENT ON COLUMN rtu_data.temperature IS '温度值（单位：℃，范围 -40~85）';
COMMENT ON COLUMN rtu_data.humidity IS '湿度值（单位：%RH，范围 0~100）';
COMMENT ON TAG rtu_data.rtu_id IS 'RTU 唯一标识（标签）';
```

**TDEngine 核心概念**：

- **超级表（STable）**：定义数据结构和标签，类似关系数据库的表结构
- **子表（Sub-table）**：每个 RTU 自动创建一个子表（如 `rtu_data_RTU001`），类似分区
- **标签（TAG）**：用于分组和过滤，类似索引字段
- **时间戳**：自动索引，支持高效时间范围查询

**子表自动创建**：
```sql
-- 插入数据时自动创建子表
INSERT INTO rtu_data USING rtu_data TAGS('RTU-001') VALUES(now, 25.5, 60.2);
INSERT INTO rtu_data USING rtu_data TAGS('RTU-002') VALUES(now, 26.8, 58.4);

-- 或者显式创建子表
CREATE TABLE IF NOT EXISTS rtu_data_RTU001 USING rtu_data TAGS('RTU-001');
CREATE TABLE IF NOT EXISTS rtu_data_RTU002 USING rtu_data TAGS('RTU-002');
```

**查询示例**：

```sql
-- 1. 查询某个 RTU 的最新数据
SELECT LAST(*) FROM rtu_data WHERE rtu_id='RTU-001';

-- 2. 查询某个时间范围的数据
SELECT * FROM rtu_data
WHERE rtu_id='RTU-001'
  AND ts >= '2026-03-13 00:00:00.000'
  AND ts < '2026-03-14 00:00:00.000';

-- 3. 查询平均值（按小时聚合）
SELECT _wstart, AVG(temperature), AVG(humidity)
FROM rtu_data
WHERE rtu_id='RTU-001'
  AND ts >= '2026-03-13 00:00:00.000'
INTERVAL(1h);

-- 4. 查询最大值和最小值
SELECT MAX(temperature), MIN(temperature), MAX(humidity), MIN(humidity)
FROM rtu_data
WHERE rtu_id='RTU-001'
  AND ts >= '2026-03-13 00:00:00.000';

-- 5. 查询所有 RTU 的最新数据（按 rtu_id 分组）
SELECT LAST(*) FROM rtu_data GROUP BY rtu_id;

-- 6. 插值查询（填充缺失数据点）
SELECT INTERP(ts, AVG(temperature))
FROM rtu_data
WHERE rtu_id='RTU-001'
  AND ts >= '2026-03-13 00:00:00.000'
EVERY(1m);
```

**数据写入示例**：
```java
// Java 代码示例（使用 TDEngine JDBC 驱动）
public class RtuDataWriter {
    private Connection connection;
    
    public void writeRtuData(String rtuId, float temperature, float humidity) {
        String sql = "INSERT INTO rtu_data USING rtu_data TAGS(?) VALUES(?, ?, ?)";
        try (PreparedStatement stmt = connection.prepareStatement(sql)) {
            stmt.setString(1, rtuId);
            stmt.setTimestamp(2, new Timestamp(System.currentTimeMillis()));
            stmt.setFloat(3, temperature);
            stmt.setFloat(4, humidity);
            stmt.executeUpdate();
        } catch (SQLException e) {
            log.error("写入 RTU 数据失败", e);
        }
    }
    
    // 批量写入（提升性能）
    public void batchWriteRtuData(List<RtuData> dataList) {
        String sql = "INSERT INTO rtu_data USING rtu_data TAGS(?) VALUES(?, ?, ?)";
        try (PreparedStatement stmt = connection.prepareStatement(sql)) {
            for (RtuData data : dataList) {
                stmt.setString(1, data.getRtuId());
                stmt.setTimestamp(2, new Timestamp(data.getTimestamp()));
                stmt.setFloat(3, data.getTemperature());
                stmt.setFloat(4, data.getHumidity());
                stmt.addBatch();
            }
            stmt.executeBatch();
        } catch (SQLException e) {
            log.error("批量写入 RTU 数据失败", e);
        }
    }
}
```

**性能指标**：
- **写入性能**：单表每秒 100 万 + 数据点
- **压缩比**：10:1（原始数据的 1/10）
- **查询延迟**：毫秒级响应
- **存储成本**：远低于传统关系数据库

## 8. 性能优化策略

### PostgreSQL 优化

1. **连接池优化**
   - 使用 HikariCP 连接池
   - 最小空闲连接：5
   - 最大连接数：20
   - 连接超时：30 秒

2. **索引优化**
   - 为常用查询字段创建索引（rtu_id、status、alarm_time）
   - 避免过度索引（影响写入性能）

3. **查询优化**
   - 使用分页查询（LIMIT/OFFSET）
   - 避免全表扫描
   - 使用 EXPLAIN 分析查询计划

4. **分区表（可选）**
   - 对 `rtu_alarm` 表按月分区
   - 提升历史数据查询性能

### TDEngine 优化

1. **数据库参数调优**
   ```sql
   CREATE DATABASE iot_rtu
   VARIABLES KEEP 3650      -- 数据保留 10 年
             BLOCKS 4       -- 内存块数量
             CACHE 16MB     -- 缓存大小
             PRECISION 'ms'; -- 毫秒精度
   ```

2. **批量写入**
   - 使用批量插入（executeBatch）
   - 每批 100-1000 条数据
   - 避免单条插入

3. **子表管理**
   - 每个 RTU 自动创建子表
   - 子表数量建议不超过 10 万

4. **数据保留策略**
   - 配置自动清理过期数据
   - 减少存储空间占用

**恢复数据库**：
```bash
# 恢复整个数据库
psql -h localhost -U iot_user iot_rtu < iot_rtu_backup.sql

# 恢复压缩备份
gunzip -c iot_rtu_backup.sql.gz | psql -h localhost -U iot_user iot_rtu
```

**定时备份脚本**（Linux crontab）：
```bash
#!/bin/bash
# backup_postgresql.sh

BACKUP_DIR="/backup/postgresql"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="iot_rtu"
DB_USER="iot_user"
DB_HOST="localhost"

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份数据库
pg_dump -h $DB_HOST -U $DB_USER $DB_NAME | gzip > $BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz

# 删除 30 天前的备份
find $BACKUP_DIR -name "*.sql.gz" -mtime +30 -delete

echo "Backup completed: ${DB_NAME}_${DATE}.sql.gz"
```

0 2 * * * /path/to/backup_postgresql.sh

### B. 常见问题解答

**Q1: 为什么使用双数据库架构？**
A: PostgreSQL 适合存储管理数据（强一致性、复杂查询），TDEngine 适合存储时序数据（高频写入、时间聚合）。双数据库架构充分发挥各自优势。

**Q2: TDEngine 数据如何备份？**
A: 使用 taosdump 工具备份和恢复，或者定期导出为 CSV 文件。

**Q3: PostgreSQL 表数据量过大怎么办？**
A: 对 `rtu_alarm` 表使用分区表（按月分区），或者定期归档历史数据。

**Q4: 如何监控数据库性能？**
A: 
- PostgreSQL: 使用 pg_stat_activity、pg_stat_user_tables 视图
- TDEngine: 使用 SHOW DATABASES、SHOW CONNECTIONS 命令
