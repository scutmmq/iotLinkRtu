本文件用于归档本轮代码 review 提出的关键问题，便于后续按优先级继续处理。

## 问题清单

### 1. P1 - Netty I/O 线程中执行阻塞 HTTP 调用

状态：`待处理`

位置：

- [BinaryFrameHandler.java](E:/Study/IT/RTU/iotLinkRtu/iotLinkRTu-rtu-gateway/src/main/java/com/scutmmq/handler/BinaryFrameHandler.java)

问题说明：

- 当前 `BinaryFrameHandler` 在认证、心跳状态同步、阈值刷新时直接调用 `httpClient.send(...)`
- 这段代码运行在 Netty event-loop 线程里
- 一旦 `web-server` 慢、超时或不可用，会阻塞同一 event-loop 上其他 RTU 的 I/O

风险：

- 心跳延迟
- 连接处理阻塞
- 多 RTU 并发时整体吞吐下降

建议方向：

- 将 HTTP 调用移出 Netty I/O 线程
- 可以改为独立业务线程池，或者异步 `sendAsync(...)` 后回调处理
- 认证路径尤其需要明确超时和失败策略

### 2. P1 - RTU secret 以 INFO 日志明文输出

状态：`待处理`

位置：

- [RtuGatewayService.java](E:/Study/IT/RTU/iotLinkRtu/iotiLinkRtu-web-server/src/main/java/com/scutmmq/web/service/RtuGatewayService.java)

问题说明：

- 注册 RTU 成功时，当前日志会输出完整 `secret`
- `secret` 是 RTU 长期认证凭据

风险：

- 任何能看 INFO 日志的人都可以恢复该 RTU 的认证材料
- 日志聚合系统中也会长期保存该凭据

建议方向：

- 从日志中移除 `secret`
- 如果确实要保留定位信息，只记录 `rtuId`、`name`，或输出掩码值

### 3. P1 - 仓库配置中提交了机器相关 PostgreSQL 密码

状态：`待处理`

位置：

- [config.properties](E:/Study/IT/RTU/iotLinkRtu/iotiLinkRtu-web-server/src/main/resources/config.properties)

问题说明：

- 当前仓库跟踪文件里包含了机器相关 PostgreSQL 密码

风险：

- 其他开发环境、CI、部署环境可能无法直接启动
- 凭据不应进入共享仓库

建议方向：

- 恢复为仓库默认值或占位值
- 使用环境变量、外部配置文件或本地覆盖配置注入真实密码
